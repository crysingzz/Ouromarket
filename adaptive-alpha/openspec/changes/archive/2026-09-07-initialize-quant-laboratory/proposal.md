# Initialize the quantitative laboratory

## Why

The repository contains a general-purpose self-modifying Ouroboros runtime. The requested investment research platform requires independent deterministic verification, risk and capital permissions. The supplied master specification spans 95 sections; implementation must expose its actual maturity instead of equating a demo result with investment alpha.

## What Changes

- Introduce an independently packaged Python 3.12 / uv project in `adaptive-alpha/`.
- Add strict domain contracts, immutable attempts/results, hash-chained audit, PostgreSQL and local SQLite support.
- Add PIT-labelled synthetic fixtures and deterministic after-cost public evaluation.
- Deploy a private hidden evaluation service with minimal feedback and durable query limits.
- Add bounded reference research jobs, hypothesis/spec artifacts, mutation/crossover and memory.
- Add independent paper risk, idempotent fills, reconciliation and operator kill switch.
- Add a functional same-origin operator UI, Docker hardening, CI and negative-path tests.
- Record deferred research/scientific integrations and master-spec acceptance gaps explicitly.

## Capabilities

### New Capabilities
- `research-orchestrator`: bounded research jobs and durable attempts.
- `knowledge-graph`: provenance and knowledge contracts; full graph deferred.
- `agent-runtime`: provider ports and trusted template reference agent.
- `experiment-registry`: immutable results and reproduction metadata.
- `evaluation-engine`: lagged after-cost deterministic demo evaluation.
- `hidden-evaluation`: separate process, ledger and restricted feedback.
- `strategy-registry`: versioned specifications and paper admission.
- `evolution-engine`: reference generations and future agent benchmarks.
- `market-data`: PIT validation and synthetic content-addressed fixtures.
- `portfolio-risk`: deterministic pretrade checks and operator emergency stop.
- `execution-engine`: internal paper fills, idempotency and reconciliation.
- `platform-security-observability`: identities, audit, UI and deployment.

## Impact

All implementation lives in a separate package. Root Ouroboros runtime, dependency lock, version carriers and UI are preserved. No externally connected LLM, data vendor or broker is enabled. No real capital operation is possible. The first slice exercises INV-001–INV-012 where applicable; live-specific invariants remain unimplemented and unreachable.

## Acceptance

A fresh installation runs through Docker; an operator creates a three-attempt job in the UI; every attempt and result is retained; repeated public evaluations are deterministic; hidden replies contain exactly verdict and score; a paper order requires successful risk checks and an operator-admitted strategy; duplicates do not fill twice; agent identities cannot trade or clear a halt; tests and OpenSpec validation pass.

The complete master-spec MVP is NOT the acceptance claim of this initial change. Literature-driven generated strategies, full statistical gates, realistic PIT market data and self-evolving agents are tracked separately in the backlog.
