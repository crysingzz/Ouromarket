# Изолированный исполнитель инженерных инструментов

Первый профиль принимает Python-функцию `run(payload)` и возвращает JSON. Он предназначен для вычислительных инструментов Ouroboros. Обычные стратегии по-прежнему проверяются ограниченным signal-python-v1. Отрецензированный harness можно поставить в устойчивую очередь проверки вручную через операторский API; автоматическое применение harness, skills и subagents в новых заданиях не включено.

Архитектура и границы доверия: [ADR 0002](adr/0002-isolated-native-tools.md). Контроллер располагается отдельно от API, агентов и брокера. Docker socket нельзя добавлять в их Compose-сервисы. Этот этап не требует торговых ключей или обращения к модели.

## Проверка на локальном Docker

Из каталога `adaptive-alpha`:

```sh
uv sync --locked
docker build -f runner/Dockerfile -t ouromarket-native-runner:local .
ALPHA_RUNNER_IMAGE=$(docker image inspect ouromarket-native-runner:local --format '{{.Id}}')
ALPHA_RUNNER_SOCKET=$(docker context inspect --format '{{.Endpoints.docker.Host}}')
uv run python scripts/runner_smoke.py \
  --socket "${ALPHA_RUNNER_SOCKET#unix://}" \
  --image-id "$ALPHA_RUNNER_IMAGE"
```

Нужен локальный Unix socket доверенного Docker daemon. Без `--gvisor` скрипт использует только заранее записанные тестовые программы: JSON-ответ, недоступность секретов/сети, ограничения времени/вывода/памяти/процессов, ошибка программы, некорректный ответ, отмена дочерних процессов и отсутствие файлов прошлого задания. Он сохраняет `.state/runner-acceptance.json` с идентификаторами образа/входа/исходника/политики, результатами и подтверждением удаления контейнеров. Это локальный проверочный отчёт, а не подписанный неизменяемый аудит.

На подготовленном Linux-хосте с проверенным gVisor ту же команду запускают с `--gvisor`. Этот флаг включает обязательный runsc, без fallback. Для рабочего `DockerRunner.run(ToolRequest(...))` runsc обязателен всегда. `development_fixtures=True` запрещает вызов `run`; остаётся только `run_fixture` по фиксированному имени. Агент не получает прямой доступ к библиотеке контроллера или его внутренним методам.

## Контракт и результаты

Исходник — до 16384 символов; весь сериализованный запрос — до 60000 байт; время — 1–30 секунд; совокупный stdout/stderr — 1024–65536 байт. JSON не допускает NaN/Infinity. Лимиты контейнера задаёт контроллер. Произвольные поля вроде mount, image или environment отклоняются. Пакеты при запуске не устанавливаются; начальный образ содержит только Python stdlib и supervisor. Результат программы должен быть единственным JSON-значением в stdout; диагностический stderr входит в общий лимит и не выдаётся как доверенный отчёт.

`SUCCESS` означает успешное вычисление и разбор JSON. `TIMEOUT`, `OUTPUT_LIMIT`, `INVALID_OUTPUT`, `TOOL_FAILED`, `RESOURCE_LIMIT` и `CANCELLED` фиксируют соответствующий исход. `RUNNER_ERROR` означает отказ транспорта/протокола. `CLEANUP_UNCONFIRMED` блокирует новые задания: нельзя считать окружение очищенным. Ни один статус не даёт право на капитал; в отчёте всегда `capital_eligible=false`.

## Восстановление

При нормальном завершении и отмене удаляется весь контейнер. `DockerRunner.recover()` выбирает контейнеры по меткам `org.ouromarket.runner.owner=ouromarket-native-tool-v1`, проверяет имя и истечение срока, затем удаляет только их. Активные задания и посторонние контейнеры не затрагиваются. При повреждённом сроке или отказе удаления контроллер блокируется. Устойчивая очередь выдаёт одному worker ограниченную аренду; просроченная аренда возобновляется, а прежний владелец больше не может записать результат.

После неопределённого create/cleanup оператор проверяет состояние Docker и контейнеры с указанной меткой, выполняет recovery после истечения срока и отдельно убеждается в отсутствии отложенных операций daemon. Только затем создаётся новый контроллер. Recovery не снимает блокировку автоматически. При падении самого контроллера требуется отдельный recovery-проход; постоянного фонового уборщика в этом срезе нет.

Для запуска очереди на принятом Linux-хосте соберите runner, закрепите его digest в `ALPHA_RUNNER_IMAGE_ID`, задайте Unix socket в `ALPHA_RUNNER_SOCKET_HOST` и его group ID в `ALPHA_RUNNER_DOCKER_GID`, затем включите профиль `native-tools`. Публичный API не получает socket; worker подключён только к сети БД и не получает секреты OpenAI, Ouroboros, evaluator или брокера.

```sh
docker compose --profile native-tools up -d tool-worker
```

Оператор создаёт проверку через `POST /api/engineering/artifacts/{artifact_id}/tool-runs`, читает её через `GET /api/engineering/tool-runs` и отменяет через `POST /api/engineering/tool-runs/{run_id}/cancel`. Исходник и payload не возвращаются в списке. До полного подключения сгенерированных инструментов остаются независимая приёмка изоляции под runsc, locked dependency profiles и операторское принятие версии инструмента для будущих WorkOrder. [План](ROADMAP.md) сохраняет эти задачи открытыми.
